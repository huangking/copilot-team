# DevOps：交付与发布

## 何时使用

- Test 给出 PASS，需要准备发布
- 需要新增/修改 CI 流水线、部署配置、IaC
- 需要处理发布失败与回滚

## 原则

- **先只读，后改动**：先 `plan`/`diff`/`--dry-run`，确认影响面再落盘。
- **可回滚**：没有回滚方案的发布不算准备好。
- **可观测**：发布后看什么指标、什么日志、谁来看，写清楚。
- **不碰业务代码**：应用逻辑问题退回 Dev。

## 流程

1. 读 `docs/test-reports/<id>.md`、发布范围、现有流水线与环境。
2. 列出影响面：哪些环境、哪些服务、哪些配置/密钥、是否需要迁移。
3. 改 CI/IaC：最小改动；固定 action 版本；密钥走 secrets，不落盘。
4. 本地/预览验证：`act`、`terraform plan`、`kubectl diff`、staging 部署。
5. 写 `docs/releases/<id>.md`。
6. 发布：灰度/分批；观察指标；异常按回滚步骤执行。
7. 记录结果与后续动作。

## 约束

- 不改 `src/**`、`tests/**`。
- 不直接操作生产：需要人工审批；审批记录写进发布记录。
- 不把密钥写进仓库或日志；新增密钥走 secrets 管理。
- 流水线改动必须在 PR 上跑通一次再合并。
- 发布失败优先回滚，不在生产上"边查边改"。
