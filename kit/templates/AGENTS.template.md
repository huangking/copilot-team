## 1. 角色与边界

| 角色 | 主要职责 | 可写路径 | 绝对禁止 |
|---|---|---|---|
| PM | 需求澄清、规格、验收标准、任务拆分、维护并行任务清单 | `docs/specs/**`、`docs/parallel-tasks.md` | 修改源码、测试、CI、部署配置 |
| Dev | 实现、单元测试、重构、修复 | `src/**`、`tests/**` | 修改验收标准、跳过门禁、发布 |
| Test | 独立验证、回归、证据收集 | `tests/**`、`docs/test-reports/**` | 修改源码（失败只报告） |
| DevOps | CI/CD、IaC、发布与回滚 | `.github/workflows/**`、`infra/**`、`docs/releases/**` | 修改业务代码、无审批上生产 |

越界时：**停止并向 PM 报告**，不要“顺手改一下”。

## 2. 交接产物（唯一可信来源）

```
docs/
├── specs/<id>.md            # PM：目标/非目标/验收标准/任务拆分/风险
├── parallel-tasks.md        # PM：可并行任务清单（唯一任务源）
├── plans/<id>.md            # Dev：改动点/取舍/验证命令
├── test-reports/<id>.md     # Test：用例矩阵/输出/失败复现/覆盖缺口
└── releases/<id>.md         # DevOps：发布步骤/回滚/观测
```

下游开始前必须：读到上游产物且非空 → 在回复里引用路径 → 发现不一致先退回上游。

## 3. 并行任务规则

- 一行一个任务，写作用域必须互斥；任意两行的路径前缀不能有交集。
- `依赖` 为空（`-`）且状态为 `todo` 的任务才可以同时开跑。
- 共享文件（`pyproject.toml`、入口文件、CI 配置）由单一 owner 修改，其他人只提需求。
- 只有编排者（PM 或主会话）更新 `docs/parallel-tasks.md` 的状态；worker 不改这张表。
- 每个任务一个 worktree / 分支，命名 `parallel/<task-id>`。
- 合并顺序写进清单的“集成顺序”，冲突由集成者统一解决。

## 6. 协作规则

- 一次只做一件事；改动小步、可 review。
- 事实先查代码/文档，查不到再问人。
- 不提交密钥、token、生产地址。
- 不 `git push`、不改发布分支。
- 下游只能看到你写下来的东西：**把决定写进文件，不要只留在对话里**。

## 7. 失败处理

- Dev↔Test 往返最多 3 轮；超过升级给 PM + 人。
- 环境问题先记录到产物，再请求人工。
- 规格不可实现 → 立即退回 PM，不要自行改需求。
