# 0001：任务板 CSV 导出

- 状态：已验证（PASS WITH RISKS，2026-11-05）
- 负责：Dev → Test → DevOps
- 来源：用户需求 "我想把任务导出到表格里，给不做开发的人看"

## 背景与目标

任务目前只能通过 `taskboard list` 在终端查看。非开发同事需要把任务导入表格软件，
因此需要一条稳定的 CSV 导出通道。

## 非目标

- 不做 Excel（`.xlsx`）导出。
- 不做远程上传、分享链接、邮件发送。
- 不改变现有 `add` / `list` / `done` 的行为与存储格式。

## 验收标准

| ID | 标准 | 验证方式 |
|---|---|---|
| AC-1 | `taskboard export --format csv` 输出表头 `id,title,done`，随后每个任务恰有一条记录，按数值 `id` 升序排列；`done` 字段只输出小写 `true` 或 `false`；成功退出码为 0 | `python3 -m pytest tests/test_export.py -q`：断言精确输出及退出码 |
| AC-2 | 标题字段含逗号、双引号、CR 或 LF 时按 RFC 4180 引号规则序列化，字段内的双引号加倍；所有记录以 CRLF 分隔 | 同上：覆盖各特殊字符及精确输出 |
| AC-3 | 空任务板仅输出表头记录，且输出以 CRLF 结束 | 同上：断言精确输出 |
| AC-4 | `--format` 只接受 `csv`；其他值向 stderr 报错、以退出码 2 结束，stdout 为空 | 同上：断言 stdout、stderr 和退出码 |
| AC-5 | 存储文件不存在时按空任务板导出：仅输出表头记录并以 CRLF 结束 | 同上：使用不存在的临时存储路径 |
| AC-6 | 存储文件为无效 JSON 或顶层不是列表时，向 stderr 输出包含 `invalid store` 的错误，不输出 CSV，退出码为 2 | 同上：分别覆盖无效 JSON 与错误顶层类型 |

## 边界与错误场景

- 标题包含 Unicode（中文、emoji）：字段内容原样保留，不做额外转义。
- 大文件：不做流式优化，本阶段任务量 < 10k。
- 存储文件损坏范围按 AC-6 定义；不扩展其他命令的存储错误行为。

## 任务拆分

| # | 任务 | 依赖 | 角色 |
|---|---|---|---|
| 1 | 实现 CSV 导出内容，覆盖排序、字段转义、Unicode 与 CRLF；添加对应领域层测试 | - | Dev |
| 2 | 增加 `export --format` 命令及格式校验，并保证加载错误不产生 CSV 输出；添加 CLI 测试 | 1 | Dev |
| 3 | 补齐 AC-1..AC-6 的自动化覆盖，运行 `make lint` 和 `make test` | 1, 2 | Dev |
| 4 | 独立核对 AC-1..AC-6，记录用例矩阵、执行结果和覆盖缺口 | 3 | Test |
| 5 | 确认无需镜像或流水线变更；若按发布流程交付，记录发布与回滚说明 | 4 | DevOps |

## 风险与回滚

- 风险：标题里的换行会影响记录边界 → 按 AC-2 引用字段并测试 CRLF 记录边界。
- 风险：错误路径混入 CSV → 测试需同时断言 stdout 为空、stderr 错误及退出码。
- 回滚：纯新增子命令，无数据迁移；回滚只需回退提交。

## 开放问题

- 无；导出编码为 UTF-8，CSV 记录分隔符为 CRLF。
